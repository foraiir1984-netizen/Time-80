# راهنمای آزمون دستگاه RC3 — Rev01

نامزد آزمون دستگاه، نه انتشار نهایی. وضعیت فعلی: APK هنوز ساخته/دریافت نشده؛ اجرای workflow به رفع دسترسی API این محیط وابسته است. این راهنما پس از دریافت APK **امضاتأییدشده** استفاده شود؛ source/export یا debug APK برای ارتقا کافی نیست.

## دریافت بسته

مسیر موجود: [Actions / build-android-apk.yml](https://github.com/foraiir1984-netizen/Time-80/actions/workflows/build-android-apk.yml)، شاخه `rc3-build-qa01`، ورودی `release=true`؛ SHA آماده ساخت `e6fa5c1968797d5bc6bdd3e442ca1b804c4c9d85`. هنگام آغاز run، head_sha باید همین مقدار باشد. فرمان مجاز پس از رفع دسترسی:

```sh
gh workflow run build-android-apk.yml \
  --repo foraiir1984-netizen/Time-80 --ref rc3-build-qa01 -f release=true
```

run ID و artifact ساخته‌شده فعلاً **Not Available** هستند؛ هیچ لینک artifact تازه‌ای ادعا نمی‌شود. نام artifact در YAML مسیر عمومی موجود `Time80-v0.2-APK` است و فایل داخلی `Time80-v0.2.apk` دارد؛ این نام تاریخی اثبات نسخه نیست. پس از استخراج مشخصات و امضای واقعی، فایل خروجی دستگاه باید `Time80-v0.3.0-RC3.apk` و checksum متناظر باشد. تا تأیید metadata و گواهی، فایل برای نصب تحویل نشده است. این workflow GitHub Release منتشر نمی‌کند.

## نصب روی RC2 بدون حذف

1. مشخصات دستگاه، Android/One UI، timezone، font scale و نسخه نصب‌شده را ثبت کنید. هدف این نامزد RC2 با package `com.personal.time80` و versionCode=4 است؛ نسخهٔ موجود ۵ یا بالاتر نیاز به بررسی versionCode تازه دارد.
2. قبل نصب، تعداد و چند نمونهٔ معلوم از فعالیت‌ها/ثبت امروز و گذشته، تنظیمات یادآوری/ساعات/روزها/صدا/لرزش و وضعیت آرشیو را ثبت کنید. داده واقعی را پاک نکنید. برای آزمون مصنوعی ارتقا، از دستگاه یا emulator جدا استفاده کنید.
3. پس از تحویل، checksum APK باید مطابق فایل checksum باشد؛ گواهی باید SHA-256 زیر را داشته باشد: `a9b10ace1c5b633458542bb3af73e4254334660718afe79f579e51c03ebbcb7d`، همان RC2. applicationId=`com.personal.time80`،versionName=`0.3.0` و versionCode=5 باید **از APK** تأیید شوند.
4. APK را روی همان برنامه نصب کنید؛ uninstall،clear data،reset یا جایگزین debug ممنوع. با adb در محیط آزمایش جدا: `adb install -r Time80-v0.3.0-RC3.apk`؛ از `-d` برای downgrade استفاده نکنید. در نصب دستی، از installer گزینهٔ update همان برنامه را انتخاب کنید.
5. خطای امضا، downgrade،identity یا داده را ثبت و متوقف کنید؛ برای عبور از خطا برنامه را حذف نکنید. پس از نصب، نمونه‌ها و تعدادهای قبل/بعد و تنظیمات را مقایسه کنید. نبود تغییر schema در سورس، شاهد موفقیت ارتقای گوشی نیست.

## اعلان و ارتقا

- A09/X69 مجوز،X70 تنظیمات گوشی،X72 هماهنگ‌سازی وX75 retry صف اثرهای جدا دارند. display/channel/exact مستقلاًثبت؛supported=false یاvalue=null نامعلوم است. cache یاreconcile شاهد دریافت نیست.
- P03-014: رد و اعطای مجدد مجوز،سپس **حداقل۳موعد متوالی**؛زمان برنامه‌ریزی/نمایش/دریافت واقعی و وضعیتforeground/lock/background هرموعد ثبت شود.
- P03-015: denied→granted→resume،بازگشتX70،تازه‌شدنdiagnostics و رفع فقطخطای متعلق بهآن خواندن/عملیات؛خطاهایbootstrap/response محفوظ.
- P03-016: پاسخpending→بازه دقیق→ثبت؛اعلان همانموردحذف،route/dismiss/ack/commit تکراری نشود؛X75صف‌خالی/درحال‌پردازش/شکست/موفقیت معناهای صحیح دارند. duplicate وUndo را با داده مصنوعی چک کنید.
- P03-019: target SDK **بسته‌شده APK**،نسخهAndroid،مجوزexact،capability واقعی و نمایش در OS-list جدا ثبت شوند. نام permission یاtargetdeclared به‌تنهایی دلیل بسته‌شدن نیست.
- ارتقا را درمحیط جدا باRC2امضاشده و داده مصنوعی معلوم نیز انجام دهید؛بدونuninstall/reset. فعالیت‌ها/ثبت‌ها/تنظیمات وsnapshot داده‌های تاریخی قبل/بعد مقایسه شوند. گوشی کاربر پاک نشود.
