# وضعیت پیاده‌سازی Time80 v0.2 — مشخصات ۱.۲

این شاخه نسخهٔ قابل بررسی پیاده‌سازی است؛ هنوز انتشار تأییدشده یا APK آزموده‌شده روی گوشی نیست.

## پیاده‌سازی‌شده

- baseline دیتابیس schema=3؛ تشخیص ساختار و محدودیت‌ها؛ ساخت اتمیک، seed فقط یک‌بار، و توقف بدون حذف/reset برای دیتابیس قدیمی یا ناشناخته.
- ledger مستقل از اعلان با افق ۳۵ روز، امروز و روزهای قبل، backlog، skip، ثبت یک‌لمسی، ویرایش با کنترل تعارض و Undo ده‌ثانیه‌ای.
- ICATUS 2016 رسمی شامل ۹/۵۶/۱۶۵ گره؛ checksum، پیش‌فرض فعالیت، snapshot منشأ تخصیص، تاریخچهٔ revision و دستهٔ خالی صریح. عناوین فارسی فعلاً برای ۹ دستهٔ اصلی هستند؛ سایر عناوین انگلیسی نمایش داده می‌شوند و تعریف رسمی از وب باز می‌شود.
- حفظ زمینهٔ زمانی هنگام ویرایش، تأیید صریح منطقه، و گزارش شکاف پوشش نامعلوم پس از تغییر منطقهٔ زمانی.
- گزارش تقویمی شمسی/میلادی، هفته و دورهٔ ۳۰روزهٔ استفاده، rolling و بازهٔ دلخواه؛ سهم زمانی، پارتو، پوشش ثبت، دسته‌های اصلی و unmapped. خواندن دورهٔ جاری و قبلی در snapshot مشترک است.
- navigation پشته‌ای و چهار tab؛ فرم فعالیت با مدیریت keyboard، جست‌وجوی آیکون، archive و چهار پیشنهاد اخیر.
- تنظیمات اتمیک، حفظ بازهٔ جاری، مبدأ فاصلهٔ جدید از پایان جاری، و بازگشت مبدأ day_start از روز کامل بعد.
- اعلان هفتگی ماندگار همراه exceptionهای انتقال، reconcile قابل تکرار، dirty flag، permission/channel، onboarding، تست اعلان و diagnostics.
- قفل وابستگی‌ها، workflow اعتبارسنجی، و ساخت release فقط با هویت امضای ثابت و fingerprint مورد انتظار.

## تصمیم اجرایی اعلان

API استاندارد WeeklyTrigger زمان «زودتر از این لحظه اجرا نشود» ندارد. patch محدود و نسخه‌محور `scripts/patch-notifications.cjs` در نصب وابستگی اعمال می‌شود و اگر محل patch تغییر کند، نصب متوقف می‌شود. این patch اولین alarm مجاز را به هفتهٔ بعد منتقل می‌کند و timestamp مطلق occurrence را پیش از ذخیرهٔ درخواست ثبت می‌کند. استمرار هفتگی همچنان با scheduler بومی Expo است؛ برنامه به بازشدن روزانه وابسته نیست.

payload بدون timestamp مطلق، به‌جای حدس‌زدن روزِ اعلان دیررس، صفحهٔ انتخاب بازه را باز می‌کند. اعلان dated زمان شروع/پایان دقیق دارد. این انتخاب محافظه‌کارانه برای payload قدیمی نیز اعمال می‌شود.

این تغییر native هنوز روی دستگاه یا با کامپایل Kotlin تأیید نشده است؛ تولید پروژهٔ Android و bundle جاوااسکریپت به‌تنهایی صحت reboot/تحویل اعلان را ثابت نمی‌کند.

## اعتبارسنجی اجراشده

- `npm run typecheck`: موفق.
- `TZ=UTC npm test`: ده آزمون یکپارچه/منطقی موفق، شامل rollback ساخت، حفظ ثبت‌ها در startup تکراری، رد دیتابیس قدیمی بدون تغییر، کنترل هم‌پوشانی و revision، Undo، null صریح، زمینهٔ زمانی، archive/ranking، snapshot گزارش، مرز ماه شمسی و DST، تغییر ۳۰→۶۰، شکست جزئی OS و retry بدون duplicate، تغییر day_start و اعلان دیررس.
- آزمون دیتابیس با SQLite واقعی Node اجرا می‌شود؛ adapter فقط رابط async Expo را شبیه‌سازی می‌کند. API اعلان OS در این آزمون‌ها شبیه‌سازی شده است.
- `expo install --check` با metadata محلی SDK: وابستگی‌ها سازگار؛ بررسی آنلاین به timeout پراکسی خورد.
- `expo export --platform android`: موفق؛ bundle Hermes تولید شد.
- `expo prebuild --platform android --no-install`: موفق؛ plugin امضای ثابت در Gradle ایجاد شد.

## پیش از انتشار روی گوشی

۱. کلید ثابت release و رمزهای آن در GitHub Secrets تنظیم و fingerprint گواهی ثبت شود. کلید یا رمز در سورس قرار نمی‌گیرد و این شاخه کلید موقتی تولید نمی‌کند.
۲. workflow ساخت release اجرا و کامپایل native، امضا و نصب APK بررسی شود.
۳. روی S23 FE: مجوز و تست ده‌ثانیه‌ای، باز/بسته بودن اپ، reboot، محدودیت باتری، تغییر فاصله وسط بازه، عبور از نیمه‌شب و تغییر منطقهٔ زمانی آزموده شود.
۴. ۳۰+ فعالیت، keyboard، Back، انتخاب دسته، ویرایش/Undo و ثبت از اعلان آزمایش شود.
۵. یک build بعدی با همان کلید روی baseline v0.2 نصب و برابری داده‌ها بررسی شود. migration نسخهٔ آینده و restore خودکار در این تحویل وجود ندارد؛ ابزار backup آماده است و migration آینده به مسیر و آزمون مخصوص خودش نیاز دارد.

این موارد gate انتشار هستند. هیچ APK امضاشده‌ای در این محیط ساخته نشده است؛ Android SDK و کلید انتشار در دسترس نیستند.

## داده‌های نسخهٔ قبلی

طبق بند ۳ مشخصات ۱.۲، مسیر هدف نصب تازهٔ v0.2 است و انتقال v0.1 پیاده‌سازی نشده است. در عین حال هیچ مسیر حذف، reset یا migration خودکار روی دیتابیس v0.1 وجود ندارد: startup متوقف می‌شود و دادهٔ موجود دست‌نخورده می‌ماند. از v0.2 به بعد حفظ داده و هویت امضای ثابت الزامی است.
